# P5.1 — the MCP transport spine

What was built, what was proved, and what is deliberately not here yet. This slice establishes
the authenticated Streamable HTTP boundary the rest of P5's conversation is built on. It adds
**two** of the five frozen intent tools and no orchestration.

The decisions behind it are recorded in [ADR-0009](adr/0009-mcp-transport-spine.md). The rules
they exist to satisfy are in the [P5 product contract](p5-product-contract.md).

## Exact identity

| | |
|---|---|
| SDK | `mcp==2.2.0` (pulls `mcp-types==2.2.0`), pinned with `==` |
| Protocol revision served | **2025-11-25**, the pinned SDK's newest `initialize` handshake revision |
| Transport | Streamable HTTP, `POST /mcp`, SSE responses (`json_response` off by default) |
| Session mode | stateless — no `Mcp-Session-Id` issued, none honoured |
| Entrypoint | `pp mcp` → `promisepatch.mcp_server:create_app` under uvicorn `--factory`, `:8001` locally |

The SDK also speaks `2026-07-28`, reached through a different entry point. That is exactly why
the pin alone is not the claim: `test_the_pinned_sdk_speaks_the_revision_we_claim` asserts the
revision and the handshake set, so an SDK bump that moved the default fails a test rather than
silently changing what the endpoint negotiates.

## The two hops

```text
MCP client  ──POST /mcp, Bearer──▶  promisepatch.mcp        ──POST /internal/intents/*──▶  promisepatch.api
(SDK, Inspector,                    (the `mcp` process)      X-Service-Token                (the `api` process)
 orchestrator, Alexa+)              no db, no domain         X-Correlation-ID               domain services
                                                                                            PostgreSQL
```

**Before the protocol.** DNS-rebinding protection rejects an unlisted `Origin` with `403` and an
unlisted `Host` with `421`. The bearer check is an ASGI middleware outside JSON-RPC, so an
unauthenticated caller gets `401` with a `WWW-Authenticate` challenge and never learns which
tools exist, what their schemas are, or whether an identifier it guessed is real.

**Identity.** The authenticated principal is published in a `ContextVar` that the middleware
sets before entering the application; the stateless transport carries no headers into a tool's
context, so a tool that finds no principal **refuses** rather than falling back to anything a
caller supplied. The *attesting worker* is a separate matter and is resolved further in: the
intent API reads `PP_SURFACE_WORKER_ID` from its own configuration. No request field anywhere in
the chain carries an actor — the tool schemas have none, and the intent schemas forbid extras.
The clock is the server's for the same reason.

**Correlation.** Every tool call mints a correlation id, returns it in the envelope, and sends
it as `X-Correlation-ID`. The intent API passes it into `intake.open_physical_exception`, which
stamps it on the governed audit row. `test_the_correlation_id_reaches_the_audit_ledger` and
`test_a_tool_call_becomes_durable_evidence` check both ends of that chain.

## Tool contracts

### `report`

| | |
|---|---|
| arguments | `text` (required, verbatim), `client_request_id` (optional idempotency key) |
| result | `{ok, intent, correlation_id, case_id, state, warnings, statement_id, created, attested_by, speech}` |
| durable effect | one `cases` row at `RECEIVED`, one `case_reports` row holding the sentence byte for byte, one `BEGIN_INTERPRETATION` step, one `CASE_OPENED` audit row |
| refusals | `INVALID_ARGUMENT` (nothing said), `UNAUTHORIZED_SURFACE`, `CASE_NOT_IN_STATE` (command id reused for different words), `ENGINE_UNAVAILABLE` |

The text is forwarded untouched — not trimmed, normalised or case-folded. `created: false` is a
success: it means this exact request was already accepted.

`client_request_id` is minted into a command id namespaced by the *authenticated principal*, so
a key is only ever a retry of that client's own call and can never address another client's
case. Because a redelivery must hash identically, the intent API reuses the `observed_at` its
own stored statement recorded rather than stamping a fresh clock
(`intake.observed_at_for`) — otherwise a retry would look like a second, different statement.

### `status`

| | |
|---|---|
| arguments | `case_id` (required) |
| result | `{ok, intent, correlation_id, case_id, state, warnings, headline, speech, needs_owner_attention, exception_category, threatened[], untouched[], untouched_count}` |
| durable effect | none; a read |
| refusals | `INVALID_ARGUMENT` (not an identifier), `UNKNOWN_RESOURCE` (no such case), `UNAUTHORIZED_SURFACE` (not this surface's case), `ENGINE_UNAVAILABLE` |

`speech` is rendered by `promisepatch.domain.status_view` from the durable case, in the intent
API, and delivered as given. The conversational layer is told — in the server's own
`instructions` — to deliver it rather than restate it. `require_permitted` runs on this read
exactly as on a write: a case id is a value a model can put in an argument, so the domain
answers, not the transport.

### The truthful vocabulary, as implemented

`status_view` projects the durable case into the P5 contract's state vocabulary and renders it.
Every phrase is bound to a posture the workflow already enforces, so nothing is re-derived:

- **"asked"** requires `WAITING_FOR_CUSTOMER` *and* a `provider_ref` on the request — which the
  workflow stamps only once the provider acknowledged delivery. A queued message reads
  `PLANNED`.
- **"changed"** requires `RECOVERED`, which is reachable only after the order system's own state
  was observed to agree. An acknowledgement leaves the track `APPLYING`.
- **"planned"** is the whole sentence for an `AUTO_RECOVERABLE` track before the worker's
  confirmation. `AUTHORIZED` needs a case state only a confirmation reaches.
- Anything unrecognised lands on `AWAITING_PLAN` — it understates, never overstates.

Two values sit outside the contract's table and are reported under their own phrasing rather
than folded into `UNTOUCHED`: `LINKED` (another case is already recovering that promise) and
`WITHDRAWN`. Calling either "left alone" would inflate the product's central claim.

## What was proved, and how

`apps/backend/tests/test_mcp_protocol.py` — **44 tests, offline**: no database, no credential,
no model, no network beyond a loopback socket. Each one drives the real server (the application
`pp mcp` runs, under uvicorn on an ephemeral port) with the official SDK client or a plain HTTP
client. The hop behind it is a recording intent API answering the real wire shape.

| area | what is checked |
|---|---|
| the pin | `mcp`/`mcp-types` are `2.2.0`; the handshake's newest revision is `2025-11-25` |
| initialization | a client offering `2025-11-25` gets it back, with server info and capabilities |
| negotiation | a client offering `1999-01-01` gets a counter-offer of `2025-11-25`, not a rejection |
| instructions | the boundary ("you cannot confirm a plan") reaches the model, not only a document |
| discovery | exactly `report` and `status`; no argument named worker/actor/observed_at/version/consent/…; both publish output schemas |
| successful calls | envelope shape, verbatim text forwarded, service token and correlation id on the wire |
| identity | an argument naming a worker changes nothing; `attested_by` stays the configured one |
| idempotency | the same `client_request_id` reaches one command; two principals with one key do not |
| invalid calls | empty text, a case id that is not one (refused before the engine), a missing argument, an unknown tool |
| refusal mapping | 401/403/404/409/422/500/503 → the stable codes, with the engine's own message withheld |
| unavailability | an engine on a dead port, and an answer missing a promised field, both refuse rather than answer |
| authentication | `401` + `WWW-Authenticate`, no tool name in the body; seven ways of not having the credential are one rejection |
| Origin / Host | unlisted `Origin` → `403`; listed → `200`; unlisted `Host` → `421` |
| protocol errors | unknown method → `-32601`; malformed JSON → `400`/`-32700` and no tool reached; a POST that will not accept an event stream → `406` |
| reconnect / resume | no `Mcp-Session-Id` is issued; a fabricated one grants nothing; a second, independent session picks the case up |

`apps/backend/tests/test_status_view.py` — **18 tests, pure**: the vocabulary rules above,
including the negative ones ("asked" absent while a message is in flight, "changed" absent
before reconciliation, an unknown posture understating).

`apps/backend/tests/test_intent_api.py` — **19 tests, PostgreSQL**: what a call *causes*. The
intent API directly (credential, identity, idempotency, conflict, correlation-to-audit,
permission, real `PLANNED` status off the canonical fixture), and then the whole chain end to
end — SDK client → Streamable HTTP → MCP server → HTTP → intent API → domain → PostgreSQL — on
two real sockets, asserting the rows afterwards over a separate connection.

Also run: `ruff check`, `ruff format --check`, `mypy` (group A, 226 files), `lint-imports`
(25 contracts kept, 0 broken), and one manual pass against the running Docker stack:
`docker compose up mcp` → `401` unauthenticated → `initialize` negotiating `2025-11-25` →
`report` → `status`, with the case visible in the database.

**No live model call was made and none was needed.** Nothing in this slice reaches a provider:
`report` stores words, `status` renders from rows. G5 item 9's bounded live conversational smoke
belongs to the slice that adds the orchestrator, because there is nothing yet for a model to
orchestrate.

## Limitations, stated

- **No SSE resumption.** Stateless mode offers no `Last-Event-ID` replay. Reconnect means a new
  handshake against a durable case, which is what the tests assert and all they assert.
- **Bearer only.** SigV4 and JWT are configuration at the edge in P6; neither is implemented or
  tested here, and no AgentCore deployment is claimed.
- **One surface worker.** `PP_SURFACE_WORKER_ID` is a single id because one conversational
  surface exists. A deployment with several would map the authenticated service principal to a
  worker — still on the server, still not a tool argument.
- **`status` is bounded.** It reports the case, the authority bands and the untouched count. The
  evidence drawer (band 5 of the case workspace) is not in the payload yet.
- **A local stack that predates this slice** cannot have `docker/env/mcp.env` generated for it
  alone: the service token is shared with `api.env`, and `bootstrap_local_env.py` refuses to
  write one side of a shared secret. Regenerate all of them (and remove the database volume) or
  write the pair by hand.
- Both holdouts remain sealed. P4.8 stays closed.

## Not in this slice

`clarify`, `confirm`, the bounded withdrawal, the orchestrator, voice, the Alexa+ simulation,
the case workspace UI, and any cloud deployment. The absent tools are absent rather than
stubbed: a tool that exists and refuses is a different thing from a tool that does not exist.
