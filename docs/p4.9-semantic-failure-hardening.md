# P4.9 — Semantic failure hardening

> **Zero model calls. Spend: $0.** Nothing on this page was measured against a live model, and
> nothing on it needed to be: every claim here is about what PromisePatch does with an answer, a
> failure or a silence, which is answerable without buying one. Neither HOLDOUT was opened, P4.8
> was not reopened, and the explanation selection is unchanged.

The property this phase set out to establish:

> A model may misunderstand, hallucinate, fail, arrive late, or be unavailable without gaining
> authority or corrupting deterministic PromisePatch state.

The authority half of that was already structural, and this audit found nothing that weakened
it. What it did find is the other half, in four places — an input, an envelope, a display label
and a persisted row — each of which could raise an exception that is **neither of the two
failures the semantic boundary promises**, while every caller of that boundary catches exactly
those two. None of the four could make a model decide anything. Three of the four could stop the
worker that decides everything, which is the same outage arriving by a different door.

---

## Method

`docs/semantic-boundary.md` names the boundary, `promisepatch.semantic` is the boundary, and
`domain.grounding`, `domain.semantic_intake`, `domain.customer_intent`, `domain.explanations`
and `domain.verbalisation` are everything that consumes it. Each was read against the threat
list, then against the existing suites — `test_semantic_contracts`, `test_semantic_provider`,
`test_semantic_grounding`, `test_semantic_intake`, `test_customer_intent`, `test_explanations`,
`test_bedrock_semantic`, `test_openai_semantic`, `evals/tests` — and a gap was counted only once
a repro had been run.

Every defect found has the same shape: **one path was hardened and its sibling was not.** The
consent protocol bounds an over-long reply; the observation path did not. The OpenAI adapter
reads every level of a response envelope defensively; the Bedrock adapter did not.
`customer_intent._label_of` refuses a persisted payload of the wrong shape; `reading_of` raised.
That asymmetry is what makes these oversights rather than decisions.

## Defects found, and the fixes

### D1 — an over-long worker statement escaped the failure vocabulary and stopped the worker

`case_reports.raw_text` is an unbounded `Text` column with only a non-empty constraint;
`UntrustedText` carries at most `MAX_UNTRUSTED_CHARACTERS` (4 000). `is_fallback_eligible` did
not look at the statement's size, so `build_request` constructed the request anyway and raised
`pydantic.ValidationError` — from `semantic_intake.prepare` in the worker's cycle, and again
from `physical` inside the execution transaction.

Nothing between there and the top catches it. `execute_step` re-raises everything that is not
`LeaseLostError`, `Worker.run_forever` catches only `SQLAlchemyError` and `OSError`, and the CLI
catches only `RuntimeError`, so the process exits. `restart: unless-stopped` brings it back, the
lease on that step expires, another claim reaches the same statement, and it exits again — one
worker sentence over the bound stops recovery for **every** case, indefinitely. The consent path
refuses an over-long reply in this exact situation and in almost these words, which is what
identifies this as a gap rather than a choice.

**Fix.** The bound is now a fourth condition on `grounding.is_fallback_eligible`, refused rather
than truncated: a reading of the first four thousand characters of something else is not a
reading, and the sentence goes to a person under the stop the lexicon reached.
`grounding.question_for` makes "may a model be asked, and what would it be asked" one pure
decision taken in that order, so the request is built only once the gate has passed;
`semantic_intake.prepare` now uses it instead of building the request first and gating
afterwards.

### D2 — a Bedrock response envelope of the wrong shape escaped as an untyped exception

`extract_tool_input` guarded the content *block* (`isinstance(block, Mapping)`) and nothing above
it; `read_usage` guarded nothing. Demonstrated: `{"output": None}`,
`{"output": {"message": None}}`, a null or non-list `content`, and a non-mapping `usage` or
`metrics` each raised `AttributeError` or `TypeError` — past the two-kind taxonomy, past every
caller, out of the worker loop. The OpenAI adapter, written later for the challenger work,
already reads every level defensively; the production adapter did not.

**Fix.** `_mapping` and `_sequence`, mirroring the OpenAI adapter. Whatever shape arrives, the
answer is the one the boundary already has a name for: the model did not call the tool
(`MISSING_TOOL_USE`). Telemetry of an unreadable shape is read as absent telemetry, because a
call that succeeded and was then failed by the shape of its own token counter would be the least
useful failure in the system.

### D3 — the retained verbaliser raised on facts that will not fit in a question

`verbalisation.prepare` built `facts.request(...)` outside its `try`. `customers.name` and
`orders.external_id` are unbounded `Text` filled from the external order system, and
`EvidenceFact.value` carries 200 characters, so a customer name longer than that raised
`pydantic.ValidationError` out of a function whose documented contract — and whose existing test
`test_preparing_a_passage_never_raises_whatever_the_provider_does` — is that it never raises,
because *a caller obliged to handle an exception is a caller that could be made to do something
other than continue*, and the recovery being explained has already been authorised.

Not reachable on the shipping path: `explain` returns the deterministic rendering before
`prepare` is called while `PP_EXPLANATION_VERBALISATION` is off, which is the default and the
P4.8 selection. It was reachable in the capability P4.8 deliberately kept whole.

**Fix.** Request construction moved inside the `try`. Facts that cannot be put to a model are
recorded as `NOT_ATTEMPTED` — no request was built, so no model was asked and nothing was learned
about one — and the deterministic renderer says the same facts, including the whole label.
Nothing is truncated.

### D4 — a persisted reading of the wrong shape raised instead of being refused

`semantic_intake.reading_of` did `payload["reading"]`, while its docstring claimed that a row
edited by hand or written by an older build "is refused here rather than becoming a binding
nobody checked". A `KeyError` inside the execution transaction is not a refusal. Not
model-reachable — it needs a payload written by a differently-shaped build, or a row edited
underneath the worker — but the sibling path (`customer_intent._label_of`) already guards exactly
this, and the docstring was making a promise the code did not keep.

**Fix.** `reading_of` returns `None` for a payload carrying no usable reading, and stays strict
about a reading it *does* carry. `physical` escalates such a row exactly as it escalates a
refused answer: no binding, and the sentence goes to a person under the stop it was always unread
for.

## Remaining accepted limitations

Limits of the design, examined and left as they are. None of them is a route to authority.

- **The quantity check is a digit comparison.** "three kilograms short" passes where "3" would be
  refused, and a fact carrying a date (`2026-09-09`) admits `2026` and `09` into the passage's
  permitted digits. It is a floor against the failure that costs somebody a cake — a figure the
  engine never computed — and `UNSUPPORTED_QUANTITY` documents it as one. Widening it means
  understanding the prose, which is the thing this boundary exists in order not to do.
- **No check over free text proves a passage is faithful.** P4.8 measured that and did not select
  the model path. What the boundary establishes is that a passage refers to nothing invented,
  omits nothing mandatory, states no figure of its own, and that the outcome on screen never
  comes from the passage at all.
- **The prompt is the second line of defence and stays there.** Every rule stated in it is
  enforced after the answer comes back. No prompt hardening was added in this phase, deliberately.
- **A model that grounds correctly can still prefer one of two readings a sentence supports.**
  That is what the clarification protocol is for, and its triggers are deterministic:
  `clarification_needed` is advice no caller reads.
- **`ClarificationContext` on the request contract is unused.** No caller populates it, because a
  clarification answer is never put to a model, and no result has an option field for a model to
  invent one into. Left in place as contract, unreached in code.
- **A deployment can still be slowed by a provider that answers late but inside its timeout.**
  Bounded per call by `PP_BEDROCK_TIMEOUT_SECONDS` and per step by the retry ladder; not bounded
  in aggregate across a sweep. The consequence is slow recovery, never wrong recovery, because no
  external effect waits on a semantic call.
- **The untrusted-text bound is now stated in two places.** `UntrustedText` enforces it and both
  consuming paths check ahead of it. The duplication is deliberate: the type is the guarantee, and
  the early check is what stops the guarantee arriving as an exception.

## Validation

Offline, and scoped to what changed: `ruff check` and `ruff format --check` over the backend;
`mypy` group A (`packages/promise-graph packages/order-contract apps/backend`); `lint-imports`
(23 contracts kept, 0 broken — the semantic boundary, the explanation stack and both vendor-SDK
contracts among them); the seven-file semantic suite that needs no database and no AWS account;
and, against the local PostgreSQL with the worker stopped, `test_semantic_intake` and
`test_customer_intent`. The frontend, the engine package, the order-system boundary and the
evaluation harness were not touched and were not re-run. **GitHub CI remains the broad regression
authority.**
